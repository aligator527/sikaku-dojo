コンテナ型の仮想化（Docker など）は、アプリケーションとその実行に必要なライブラリをコンテナにまとめ、ホスト OS のカーネルを共有して動かす方式です。ゲスト OS を起動しないため軽量で、起動も速く、1 台のサーバで多くのコンテナを動かせます。したがってアが正解です。

### 各選択肢の検討

- **ア（正解）**：その反面、ホスト OS と異なる種類の OS をコンテナとして動かすことはできず、カーネルを共有する分、仮想マシンに比べて分離の強さは劣ります。
- **イ**：ハイパーバイザ型では、仮想マシンごとにゲスト OS を動かします。カーネルを共有するのはコンテナ型の特徴です。
- **ウ**：ハードウェア上で直接ハイパーバイザを動かすのは**ハイパーバイザ型**（ベアメタル型）です。ホスト型は、ホスト OS 上に仮想化ソフトウェアをインストールして仮想マシンを動かす方式で、ホスト OS を経由する分、オーバーヘッドが大きくなります。
- **エ**：ライブマイグレーションは、仮想マシンを**稼働させたまま**、別の物理サーバへ移動させる技術です。物理サーバの保守やリソースの負荷分散のときに、サービスを止めずに済みます。

### ポイント

| 方式 | 構成 | 特徴 |
| --- | --- | --- |
| ホスト型 | ハードウェア → ホスト OS → 仮想化ソフト → ゲスト OS | 導入が手軽。オーバーヘッドが大きい |
| ハイパーバイザ型 | ハードウェア → ハイパーバイザ → ゲスト OS | オーバーヘッドが小さい。サーバ統合の主流 |
| コンテナ型 | ハードウェア → ホスト OS → コンテナエンジン → コンテナ | 軽量・高速。カーネルを共有 |

クラウドの IaaS は主にハイパーバイザ型の仮想マシン、PaaS や開発・運用の自動化ではコンテナが多く使われます。

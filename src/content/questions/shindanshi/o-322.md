  次の「売上」表に対して，下の SQL 文を実行した。得られる結果（行の並び順を含む）として，最も適切なものはどれか。

  | 伝票番号 | 店舗 | 分類 | 金額 |
  | ---: | --- | --- | ---: |
  | 1 | A | 食品 | 300 |
  | 2 | A | 日用品 | 200 |
  | 3 | B | 食品 | 500 |
  | 4 | A | 食品 | 400 |
  | 5 | C | 日用品 | 150 |
  | 6 | B | 日用品 | 250 |
  | 7 | C | 食品 | 450 |
  | 8 | B | 食品 | 100 |
  | 9 | A | 日用品 | 120 |
  | 10 | C | 食品 | 180 |

  ```sql
  SELECT 店舗, SUM(金額) AS 合計
  FROM 売上
  WHERE 金額 >= 200
  GROUP BY 店舗
  HAVING COUNT(*) >= 2
  ORDER BY 合計 DESC
  ```
choices:

  - A 900，B 750，C 450 の 3 行（この順）
  - A 900，B 750 の 2 行（この順）
  - B 750，A 900 の 2 行（この順）

SQL は、WHERE で行を絞り込み → GROUP BY でグループ化 → HAVING でグループを絞り込み → ORDER BY で並べ替え、の順に処理されます。金額 200 以上の行だけで店舗ごとに集計すると、A は 3 行で 900、B は 2 行で 750、C は 1 行で 450 です。HAVING COUNT(*) >= 2 により C が除かれ、合計の降順に A、B の 2 行が得られるので、ウが正解です。

### 処理の流れ

1. **WHERE 金額 >= 200**：伝票番号 1, 2, 3, 4, 6, 7 の 6 行が残ります（5, 8, 9, 10 は除外）。
2. **GROUP BY 店舗**：A（300, 200, 400）、B（500, 250）、C（450）。
3. **HAVING COUNT(*) >= 2**：件数が 2 以上の A（3 件）と B（2 件）が残ります。
4. **ORDER BY 合計 DESC**：A（900）、B（750）の順になります。

### 各選択肢の検討

- **ア**：WHERE 句を無視して、全行で集計した結果です。
- **イ**：HAVING の件数を、WHERE で絞り込む前の行数で判定した誤りです。C は絞り込み前なら 3 行ありますが、金額 200 以上の行は 1 行だけです。HAVING は、WHERE で残った行をグループ化した後に適用されます。
- **ウ（正解）**：WHERE → GROUP BY → HAVING → ORDER BY の順に処理した結果です。
- **エ**：DESC（降順）を昇順と取り違えた並びです。
- **オ**：HAVING COUNT(*) >= 2 を「2 より大きい」と読み違え、件数 3 の A だけを残した誤りです。

### ポイント

- WHERE は集計前の**行**の条件、HAVING は集計後の**グループ**の条件です。SUM や COUNT などの集約関数を条件に使えるのは HAVING です。
- ORDER BY の既定は昇順（ASC）で、降順にするには DESC を指定します。

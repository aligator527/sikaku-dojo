コンテナ型の仮想化は、ゲスト OS を起動せず、ホスト OS のカーネルの機能（名前空間による分離や、cgroups による資源の制限）でプロセスの実行環境を分けます。OS の起動が不要なので軽量で、数秒以内に起動でき、ライブラリやその版をイメージにまとめて同じ環境を再現しやすいため、深層学習の開発環境の構築によく使われます。

### 各選択肢の検討

- **A** ハードウェアの上で直接ハイパーバイザーが動作するのは、ハイパーバイザー型（ベアメタル型）の説明です。
- **B** ホスト OS の上で仮想化ソフトウェアを動かすのは、ホスト型の説明です。A と B は説明が入れ替わっています。
- **C（正解）** コンテナ型の仮想化の説明として適切です。
- **D** コンテナはホストのカーネルを共有するため、ホストと異なるカーネルを必要とする OS 用のアプリケーションは、そのままでは動きません。異なる OS を動かしたい場合は、ゲスト OS ごと仮想化する方式を使います。

### ポイント

| 方式 | 構成 | 特徴 |
| --- | --- | --- |
| ホスト型 | ハードウェア → ホスト OS → 仮想化ソフトウェア → ゲスト OS | 導入が手軽。ホスト OS を経由するため処理が重くなりやすい |
| ハイパーバイザー型 | ハードウェア → ハイパーバイザー → ゲスト OS | ホスト OS を介さず効率がよい。サーバの仮想化で主流 |
| コンテナ型 | ハードウェア → ホスト OS → コンテナエンジン → コンテナ | ゲスト OS が不要で軽量・高速。カーネルはホストと共有 |

- コンテナ型の代表的なソフトウェアが Docker です。

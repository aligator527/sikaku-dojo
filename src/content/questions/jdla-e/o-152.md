$\log\mathrm{softmax}(\boldsymbol z)_k = z_k - \log\sum_j e^{z_j}$ と式変形してから計算するのが安定な方法（log-sum-exp）です。最大値を引いた後の `z` は各行の最大が 0 なので、`np.exp(z)` はオーバーフローせず、和は 1 以上になるので `np.log` の引数が 0 になることもありません。（あ）は C です。

### 計算

最大値 $c = \max_j z_j$ を引いても結果は変わりません。

$$\log\frac{e^{z_k}}{\sum_j e^{z_j}} = \log\frac{e^{z_k - c}}{\sum_j e^{z_j - c}} = (z_k - c) - \log\sum_j e^{z_j - c}$$

1 行目のデータでは、最大値を引いた後の `z` は `[0, -1000, -2000]` です。正解クラス 2 の対数確率は $-2000 - \log(1 + e^{-1000} + e^{-2000}) \approx -2000$ で、損失 2000 という有限の値が正しく得られます。

### 各選択肢の検討

- **A** `keepdims` がないため和の形状が `(N,)` になり、`(N, K)` の `z` とブロードキャストすると末尾の軸どうし（$K = 3$ と $N = 4$）が比べられてエラーになります（$N = K$ なら黙って誤った値になります）。
- **B** `axis=0` はミニバッチ方向の和です。ソフトマックスはサンプルごとにクラス方向で正規化するので、誤った値になります。
- **C（正解）** 行ごと（クラス方向）に log-sum-exp を計算し、`keepdims=True` で形状 `(N, 1)` を保ってブロードキャストしています。
- **D** 数学的には同じ式ですが、先にソフトマックスを計算すると、1 行目の $e^{-2000}$ が 0 にアンダーフローし、`np.log(0)` が `-inf` になって損失が `inf` になります。

### ポイント

- 最大値を引くのはオーバーフロー対策、対数の中で割り算をせず `z - logsumexp` の形にするのはアンダーフロー対策です。両方そろって数値的に安定になります。
- PyTorch の `F.cross_entropy` や `F.log_softmax` は内部でこの計算を行うので、ソフトマックスの出力ではなくロジットを渡します。
- `scipy.special.logsumexp` や `torch.logsumexp` を使うと、同じ計算を 1 行で書けます。

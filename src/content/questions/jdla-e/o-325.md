  次のコードは、エポックごとに記録した検証データの損失 `val_losses`（エポック 1 から順に並べたもの）を用いて、早期終了の判定を再現したものである。`best_epoch` のパラメータを最終的なモデルとして採用する。このコードを実行したときに表示される内容として正しいものを選べ。

  ```python
  val_losses = [0.92, 0.75, 0.68, 0.70, 0.66, 0.67, 0.66, 0.69, 0.64, 0.63]
  patience = 3

  best, best_epoch, wait = float('inf'), 0, 0
  for epoch, loss in enumerate(val_losses, start=1):
      if loss < best:
          best, best_epoch, wait = loss, epoch, 0
      else:
          wait += 1
          if wait >= patience:
              break
  print(epoch, best_epoch)
  ```
choices:

  - '`7 5`'
  - '`10 10`'
  - '`8 8`'
answer: 1

検証損失が最良値を更新しなかったエポックが 3 回連続した時点で打ち切ります。最良値はエポック 5 の 0.66 で、エポック 6・7・8 で更新がなく `wait` が 3 になるので、エポック 8 でループを抜けます。表示は `8 5` です。

### 計算

| epoch | loss | 判定 | best（best_epoch） | wait |
| --- | --- | --- | --- | --- |
| 1 | 0.92 | 更新 | 0.92（1） | 0 |
| 2 | 0.75 | 更新 | 0.75（2） | 0 |
| 3 | 0.68 | 更新 | 0.68（3） | 0 |
| 4 | 0.70 | 更新なし | 0.68（3） | 1 |
| 5 | 0.66 | 更新 | 0.66（5） | 0 |
| 6 | 0.67 | 更新なし | 0.66（5） | 1 |
| 7 | 0.66 | 更新なし（等しいだけ） | 0.66（5） | 2 |
| 8 | 0.69 | 更新なし | 0.66（5） | 3 → 打ち切り |

### 各選択肢の検討

- **A（正解）** エポック 8 で打ち切り、エポック 5 のパラメータを採用します。
- **B** エポック 5 で最良値を更新したときに `wait` を 0 に戻すのを見落とし、エポック 4・6・7 で 3 回目に達したと数えています。
- **C** 比較を `loss <= best` と読み違えると、エポック 7 で「更新」扱いになって `wait` が 0 に戻り、最後まで打ち切られません。
- **D** `best_epoch` は最良値を更新したときにだけ書き換わります。打ち切ったエポックとは別の変数です。

### ポイント

- 早期終了では、最良のエポックのパラメータを保存しておき（チェックポイント）、打ち切り後にそれを読み込んで使います。打ち切った時点のパラメータは、すでに過学習が進んでいます。
- `patience` が小さすぎると、一時的な揺れで早く止まりすぎます。この例でも、エポック 9・10 で損失はさらに下がっています。`patience` は検証損失の揺れの大きさに合わせて選ぶハイパーパラメータです。

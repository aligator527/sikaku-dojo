`BatchNorm2d` はチャネルごとに、ミニバッチと空間方向（$N, H, W$）をまとめて平均・分散を計算します。各チャネルは $8 \times 32 \times 32 = 8192$ 個の値から統計量を求め、正規化後にチャネルごとのスケール $\gamma$ とシフト $\beta$（各 16 個、計 32 個）を適用します。

### 各選択肢の検討

- **A** `BatchNorm2d` は空間位置ごとではなくチャネルごとに統計量をとり、$\gamma, \beta$ も同じチャネルの全位置で共有します。位置ごとに別々のパラメータを持たせると、畳み込み層の「位置によらず同じ処理をする」性質が失われます。
- **B** サンプルごとに $(C, H, W)$ 全体で統計量をとるのは Layer Normalization です（チャネルをグループに分けると Group Normalization、チャネルごと・サンプルごとなら Instance Normalization）。
- **C（正解）** `sum(p.numel() for p in bn.parameters())` は $16 + 16 = 32$ です。
- **D** `eval()` では、学習中に指数移動平均で蓄積した `running_mean` と `running_var` を使って正規化します。これらはバッファで、学習可能なパラメータには数えられません。

### ポイント

- 正規化手法の違いは「どの軸で平均・分散をとるか」で整理します。BN は $(N, H, W)$、LN は $(C, H, W)$、IN は $(H, W)$、GN はチャネルのグループと $(H, W)$ です。
- BN はミニバッチの統計量に依存するため、バッチサイズが小さいと不安定になります。系列長が可変の自然言語処理や Transformer では LN が標準的に使われます。
- PyTorch では、学習時の正規化には標本分散（$N$ で割る）を、`running_var` の更新には不偏分散を使います。

  深層学習の実行環境を作るために、次の Dockerfile を用意した。この Dockerfile に関する記述として、正しいものをすべて選べ。

  ```dockerfile
  FROM python:3.12-slim
  WORKDIR /app
  COPY requirements.txt .
  RUN pip install --no-cache-dir -r requirements.txt
  COPY . .
  CMD ["python", "train.py"]
  ```
choices:
  - '`RUN` に書いたコマンドは、このイメージからコンテナを起動するたびに毎回実行される'
  - '`FROM` はベースとなるイメージを指定する命令であり、この Dockerfile は Python 3.12 のイメージを土台にして新しいイメージを作る'
  - '`CMD` に書いたコマンドはイメージのビルド時に実行され、その実行結果がイメージに保存される'

Dockerfile の命令は、上から順に実行されて**イメージのビルド時**に層（レイヤ）を作ります。`RUN` はビルド時に実行され、`CMD` はコンテナの起動時に実行する既定のコマンドを指定します。変更のあった命令とそれ以降の層だけが作り直されるので、変更の少ないものを先に書くとビルドが速くなります。

### 各選択肢の検討

- **A（誤り）** `RUN` はビルド時に 1 回だけ実行され、その結果（インストールしたライブラリなど）がイメージの層として保存されます。コンテナの起動時には実行されません。
- **B（正しい）** `FROM` で指定したイメージの上に、以降の命令の結果を重ねていきます。
- **C（誤り）** `CMD` はビルド時には実行されず、`docker run` でコンテナを起動したときに実行されるコマンドを指定します。`docker run` の引数で別のコマンドを指定すると置き換えられます。
- **D（誤り）** `COPY` はビルド時にファイルをイメージ内にコピーする命令です。起動時にホストのディレクトリを共有するのは、`docker run -v ホストのパス:コンテナのパス` で指定するバインドマウントです。
- **E（正しい）** `requirements.txt` が変わらなければ `COPY requirements.txt .` と `RUN pip install ...` の層はキャッシュが使われ、`COPY . .` 以降だけが作り直されます。ソースコードを先にまとめてコピーすると、コードを変えるたびにライブラリを入れ直すことになります。

### ポイント

- イメージは `docker build -t イメージ名 .`、コンテナの起動は `docker run イメージ名` で行います。ビルドに不要なファイル（データセットや仮想環境など）は `.dockerignore` で除外します。
- 再現性のために、ベースイメージのタグや `requirements.txt` のライブラリの版を固定しておきます。
- `ENTRYPOINT` は起動時に必ず実行するコマンドを指定し、`CMD` はその既定の引数を与える用途にも使えます。

  import torch
  import torch.nn as nn
  import torch.nn.functional as F

  V, E, H = 1000, 32, 64           # 語彙数・埋め込みの次元・隠れ状態の次元

  class RNNLM(nn.Module):
      def __init__(self):
          super().__init__()
          self.emb = nn.Embedding(V, E)
          self.rnn = nn.RNN(E, H, batch_first=True)
          self.out = nn.Linear(H, V)

      def forward(self, x):                # x: (N, T)
          h, _ = self.rnn(self.emb(x))     # (N, T, H)
          return self.out(h)               # (N, T, V)

  model = RNNLM()
  tokens = torch.randint(0, V, (8, 21))    # 長さ 21 のトークン ID 列が 8 本

  t = tokens[:, （い）]

  loss = F.cross_entropy(logits.reshape(-1, V), t.reshape(-1))

言語モデルでは、時刻 $t$ までのトークン $w_1, \dots, w_t$ を入力して、次のトークン $w_{t+1}$ を予測します。入力は最後のトークンを除いた `tokens[:, :-1]`、正解は先頭を除いて 1 つずらした `tokens[:, 1:]` です。どちらも長さ 20 になり、コメントの形状とも一致します。

### 各選択肢の検討

- **A** 入力を 1 つ先にずらしているので、時刻 $k$ の正解 $w_k$ はすでに 1 つ前の時刻で入力として見ています。直前の入力をそのまま答えるだけの課題になり、言語モデルとして意味がありません。
- **B（正解）** 入力 $w_1, \dots, w_{20}$ に対し、正解は $w_2, \dots, w_{21}$ です。
- **C** 入力と正解が同じで、現在の入力をそのまま出力（コピー）すれば損失が下がってしまいます。
- **D** 入力が長さ 21 なので `logits` は `(8, 21, V)` となり、長さ 20 の正解と要素数が合わずに `cross_entropy` でエラーになります。

### ポイント

- `F.cross_entropy` はクラスの次元が 2 番目にある `(N, C)` 形式を受け取るので、時刻の次元をバッチの次元とまとめて `(N·T, V)` と `(N·T,)` に変形してから渡しています。
- 推論（文章の生成）では、予測したトークンを次の時刻の入力にして 1 つずつ生成します。GPT などの Transformer の言語モデルも、同じ「1 つずらし」で next token prediction を学習します。
- 言語モデルの評価には、交差エントロピー（自然対数）の平均 $\bar L$ から求めるパープレキシティ $e^{\bar L}$ がよく使われます。

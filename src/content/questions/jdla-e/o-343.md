学習時はミニバッチの平均 `mu` と分散 `var` で正規化し、同時に推論用の移動平均 `running_mean`、`running_var` を更新します。推論時は入力のミニバッチの統計量ではなく、学習中に蓄えた移動平均で正規化します。

### 各選択肢の検討

- **A（正解）** 学習時はミニバッチの統計量、推論時は移動平均を使っています。分母は分散に $\varepsilon$ を足した値の平方根（標準偏差）です。
- **B** 推論時にも入力の統計量を使っています。予測が同時に入力した他のサンプルに左右され、1 サンプルずつ推論すると $x - \bar x = 0$ となって出力がすべて $\beta$ になってしまいます。
- **C** 学習時と推論時が逆です。推論時の分岐では `mu` と `var` が定義されていないので、`NameError` になります。
- **D** 平方根をとり忘れています。分散で割ると、正規化後の値の大きさが入力のスケールに依存してしまいます。

### ポイント

- このコードの `momentum` は「過去の移動平均を残す割合」です。PyTorch の `nn.BatchNorm1d` の `momentum`（既定 0.1）は「新しいミニバッチの統計量を取り込む割合」で、意味が逆です。Keras の `momentum`（既定 0.99）はこのコードと同じ意味です。
- 推論時の Batch Normalization は固定の線形変換 $y = a x + b$ になるので、直前の全結合層や畳み込み層の重みに統合（folding）して計算を省くことができます。
- PyTorch では `model.train()` と `model.eval()` で、この分岐が切り替わります。

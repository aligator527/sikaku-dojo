ソフトマックス関数は、同じ行のすべての成分から同じ定数 $c$ を引いても値が変わりません。各行の最大値を引くと、指数関数に入る値は $0$ 以下になってオーバーフローせず、最大の成分は $e^0 = 1$ になるので分母が 0 になることもありません。形状 `(N, 1)` で引くために `keepdims=True` が必要です。

### 計算

$$\frac{\exp(z_k - c)}{\sum_j \exp(z_j - c)} = \frac{e^{-c}\exp(z_k)}{e^{-c}\sum_j \exp(z_j)} = \frac{\exp(z_k)}{\sum_j \exp(z_j)}$$

`float64` の `np.exp` は引数が約 $709.8$ を超えると `inf` になるので、そのまま計算すると 1 行目は `inf / inf` で `nan` になります。各行の最大値を引くと、1 行目は $(-2, -1, 0)$ となり、3 行目と同じ $(0.090, 0.245, 0.665)$ が得られます。

### 各選択肢の検討

- **A** `axis=0` は列ごとの最大値 $(1000, 1001, 1002)$ です。1 行目からは列ごとに異なる値が引かれて $(0, 0, 0)$ となり、結果が一様分布に変わってしまいます。3・4 行目はすべての成分が $-999$ 以下になって `np.exp` が 0 にアンダーフローし、`0 / 0` で `nan` になります。
- **B** `keepdims` がないと形状が `(4,)` になり、`(4, 3)` の `x` と後ろの軸どうしでブロードキャストしようとして `ValueError` になります。$N = C$ のときはエラーにならずに誤った軸で引かれてしまい、さらに気づきにくくなります。
- **C** 行ごとの定数を引くので数学的には同じ値になりますが、引いた後の値は $0$ 以上です。2 行目は $(0, 1000, 2000)$ となり、オーバーフローを防げません。
- **D（正解）** 各行の最大値を形状 `(4, 1)` で引いています。

### ポイント

- 交差エントロピー誤差と組み合わせるときは、$\log y_k = z_k - c - \log\sum_j \exp(z_j - c)$（log-sum-exp の形）で計算すると、$\log 0$ も避けられます。PyTorch の `nn.CrossEntropyLoss` がロジットを受け取るのは、内部でこの安定な計算を行うためです。
- 同じ考え方で、シグモイド関数も $x$ の符号で式を切り替えて $e^{-x}$ のオーバーフローを避ける実装が使われます。

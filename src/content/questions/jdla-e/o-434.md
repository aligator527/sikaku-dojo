  長いテキストを長さ 35 ずつのチャンクに区切り、先頭から順に LSTM 言語モデルを学習する。チャンクをまたいで隠れ状態を引き継ぎつつ、逆伝播はチャンクの中だけで打ち切る truncated BPTT を行いたい。次の PyTorch のコードの空欄（あ）に入るものとして正しいものを選べ。

  ```python
  # model(x, state) は (logits, state) を返す。state は (h, c) のタプル
  state = None                       # 最初のチャンクは初期状態（ゼロ）から
  for x, t in chunks:                # チャンクを系列の順番どおりに取り出す
      （あ）
      logits, state = model(x, state)
      loss = criterion(logits.reshape(-1, V), t.reshape(-1))
      optimizer.zero_grad()
      loss.backward()
      optimizer.step()
  ```
choices:
  - '`state = None`'
  - '`pass`（何もしない）'
  - '`if state is not None: state = tuple(s.detach() for s in state)`'
  - '`if state is not None: state = tuple(s.clone() for s in state)`'
answer: 3

`detach()` は値をそのまま保ちつつ、計算グラフから切り離したテンソルを返します。前のチャンクの最終状態を `detach()` してから渡すと、順伝播では前のチャンクの文脈を引き継ぎ、逆伝播は現在のチャンクの先頭で止まります。これが truncated BPTT です。

### 各選択肢の検討

- **A** 毎回初期状態に戻すので、逆伝播はチャンク内で止まりますが、前のチャンクの文脈も引き継がれません。チャンクを独立な短い系列として学習することになり、問題の要件（隠れ状態の引き継ぎ）を満たしません。
- **B** `state` が前のチャンクの計算グラフにつながったままなので、2 つ目のチャンクの `loss.backward()` が前のチャンクのグラフまで遡ろうとします。前のチャンクのグラフは 1 回目の `backward()` で解放されているため、`RuntimeError`（Trying to backward through the graph a second time）になります。解放しないようにしても、系列の先頭まで遡るので計算量とメモリが増え続けます。
- **C（正解）** 順伝播は引き継ぎ、逆伝播は打ち切るという要件を満たします。
- **D** `clone()` は値をコピーしますが、計算グラフとのつながりは残ります（コピー操作自体も微分可能な演算として記録されます）。B と同じエラーになります。

### ポイント

- truncated BPTT では、打ち切り長（ここでは 35）より前へは勾配が流れないので、それより長い依存関係は勾配を通じては学習できません。ただし順伝播の隠れ状態は引き継がれるため、長い文脈の情報は入力として利用できます。
- チャンクを順番どおりに処理するには、データをシャッフルせず、各ミニバッチの行がそれぞれ連続したテキストの続きになるように並べる必要があります。

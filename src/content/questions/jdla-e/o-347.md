毎回、古い値を 0.9 倍し、新しいミニバッチの平均の 0.1 倍を足します。$0 \to 0.2 \to 0.58 \to 0.822$ と変化し、3 回更新した後は $0.822$ です。ミニバッチの平均は 3 前後なのに、初期値 0 の影響がまだ大きく残っています。

### 計算

$$\hat\mu_1 = 0.9 \times 0 + 0.1 \times 2.0 = 0.2$$

$$\hat\mu_2 = 0.9 \times 0.2 + 0.1 \times 4.0 = 0.18 + 0.4 = 0.58$$

$$\hat\mu_3 = 0.9 \times 0.58 + 0.1 \times 3.0 = 0.522 + 0.3 = 0.822$$

### ポイント

- 係数を取り違えて $\hat\mu \leftarrow 0.1\,\hat\mu + 0.9\,\mu_B$ とすると $3.078$ になります。PyTorch の `momentum` は「新しい値を取り込む割合」、Keras の `BatchNormalization(momentum=0.99)` は「古い値を残す割合」で、同じ名前でも意味が逆です。
- 移動平均は初期値に引きずられるので、学習の回数が少ないうちに `eval()` で推論すると、正規化がずれて精度が大きく落ちることがあります。
- `running_var` も同じ式で更新されます（初期値は 1）。推論時はこれらの移動平均を使って正規化します。

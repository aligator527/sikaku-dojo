PyTorch の `nn.Dropout` は inverted dropout です。学習時は各要素を確率 $p = 0.2$ で 0 にし、残りを $1/(1-p) = 1.25$ 倍して期待値を保ちます。推論時（`eval()`）は何もせず入力をそのまま返すので、`y_eval` はすべて 1 です。

### 各選択肢の検討

- **A** 学習時にスケーリングせず、推論時に $(1-p)$ 倍する「元論文の方式」の説明です。PyTorch の実装とは異なります。
- **B** スケーリングの向きが逆です。残った要素を $(1-p)$ 倍すると期待値が $0.8 \times 0.8 = 0.64$ に下がってしまいます。
- **C** `eval()` ではドロップアウトは無効になり、要素が 0 になることはありません。
- **D（正解）** 学習時の期待値は $0.8 \times 1.25 + 0.2 \times 0 = 1$ で、推論時の出力 1 と一致します。

### ポイント

- `p` は「残す確率」ではなく「0 にする確率」です。Keras / TensorFlow の `Dropout(rate)` も同様に、`rate` は落とす割合です。
- 推論時に `model.eval()` を呼び忘れると、ドロップアウトが有効なままになり予測が毎回ぶれます（Batch Normalization も学習時の挙動のままになります）。
- ドロップアウトは、多数のサブネットワークを同時に学習して平均するアンサンブルの近似と解釈できます。ドロップコネクトはユニットではなく重みを確率的に 0 にする手法です。

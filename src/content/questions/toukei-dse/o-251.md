  UNIX 時刻（秒）のように大きな値をもつデータの分散を、2 通りの式で計算する次の Python のコードを実行する。`float` は IEEE 754 倍精度浮動小数点数（仮数部 53 ビット）である。

  ```python
  xs = [1e9 + 4, 1e9 + 7, 1e9 + 13, 1e9 + 16]
  n = len(xs)
  m = sum(xs) / n
  v1 = sum(x * x for x in xs) / n - m * m      # 2 乗の平均 - 平均の 2 乗
  v2 = sum((x - m) ** 2 for x in xs) / n       # 偏差の 2 乗の平均
  print(v1, v2)
  ```

  出力として正しいものを次のうちから一つ選べ。

answer: 5

データから $10^9$ を引くと $4, 7, 13, 16$ で、平均 10、偏差 $-6, -3, 3, 6$ より、正しい分散（$n$ で割る）は $(36 + 9 + 9 + 36)/4 = 22.5$ です。`v2` は先に平均を引いてから 2 乗するので、偏差が小さな整数になり正確に 22.5 が得られます。`v1` では $x^2 \approx 10^{18}$ どうしの引き算になり、倍精度の有効桁数（約 16 桁）では差の 22.5 が丸め誤差に埋もれて、結果は 0.0 になります（桁落ち）。

### 計算

倍精度浮動小数点数は、$2^{59} \leq x < 2^{60}$（約 $5.8 \times 10^{17}$〜$1.2 \times 10^{18}$）の範囲では $2^{59 - 52} = 128$ 刻みの値しか表せません。

- $x^2$ や $m^2$ は約 $10^{18}$ なので、計算のたびに最大 64 程度の丸め誤差が生じます。
- 求めたい差 $\overline{x^2} - m^2 = 22.5$ はこの刻み 128 より小さく、`sum(x * x for x in xs) / n` と `m * m` はどちらも同じ浮動小数点数 $1000000020000000128$ に丸められます。その差が 0.0 です。

`xs` の各値（$10^9 + 4$ など）と平均 $m = 10^9 + 10$ は $2^{53} \approx 9 \times 10^{15}$ より十分小さい整数なので正確に表せ、`x - m` は $-6, -3, 3, 6$ と正確に計算されます。

### 各選択肢の検討

- ①：数学的にはどちらの式も 22.5 ですが、浮動小数点数の計算では `v1` に桁落ちが起こります。
- ②：誤差が出るのは、大きな数どうしを引く `v1` の方です。
- ③：`v1` は桁落ちで負になることもありえますが、この入力では 0.0 です。符号だけが反転するわけではありません。
- ④：`v2` は偏差を先に計算するので、大きな数の引き算による誤差は生じません。
- ⑤：正しい。

### ポイント

- 桁落ち：ほぼ等しい 2 つの数を引くと、有効数字が大きく失われる。分散の公式 $E[X^2] - (E[X])^2$ は手計算では便利だが、平均が標準偏差に比べて大きいデータでは数値的に不安定である。
- 対策：平均を引いてから 2 乗する 2 パスのアルゴリズム、データを 1 回走査しながら平均と偏差平方和を更新するウェルフォード（Welford）のアルゴリズム、適当な値（最初のデータなど）を引いてから計算する方法。
- `numpy.var` や `statistics.pvariance` は、平均を引いてから計算する安定な方法を使っている。

ステータスコード 429（Too Many Requests）は、利用者が一定時間内のリクエスト数の上限（レート制限）を超えたことを表します。応答に `Retry-After` ヘッダーがあればその時間だけ待ち、なければ待ち時間を 1 秒、2 秒、4 秒…と延ばしながら再試行するのが一般的です。

### 各選択肢の検討

- ①：404（Not Found）は、要求したリソースが存在しないことを表すクライアント側のエラー（4xx）です。URL を見直さずに繰り返しても成功しません。サーバー内部のエラーは 500 番台（500 Internal Server Error、503 Service Unavailable など）です。
- ②：robots.txt はクローラーに対する「お願い」を書いたテキストファイルで、アクセスを技術的に遮断するものではありません。守らなくても取得はできてしまいますが、サイト運営者の意思として尊重すべきものです。利用規約の確認やサーバーに負荷をかけない間隔の設定も必要です。
- ③：GET はリソースの取得に使うメソッドで、サーバーの状態を変えない（安全で冪等な）操作とされます。データの新規作成には一般に POST を使います。
- ④：HTTPS は通信経路を暗号化しますが、受信したサーバーでは URL（クエリ文字列を含む）が復号され、アクセスログなどに記録されることがあります。API キーはリクエストヘッダーに入れるのが一般的です。
- ⑤：正しい。そもそも上限を超えないよう、リクエストの間隔を空けて収集します。

### ポイント

| 区分 | 意味 | 例 |
| --- | --- | --- |
| 2xx | 成功 | 200 OK、201 Created |
| 3xx | リダイレクト | 301 Moved Permanently、304 Not Modified |
| 4xx | クライアント側の誤り | 400 Bad Request、401 Unauthorized、403 Forbidden、404 Not Found、429 Too Many Requests |
| 5xx | サーバー側の誤り | 500 Internal Server Error、503 Service Unavailable |

- API が使える場合は、スクレイピング（HTML の解析）より API を優先する。HTML の構造は予告なく変わることがある。
- 多数の結果を返す API はページ分割（ページネーション）されていることが多く、次ページの指定を繰り返して全件を取得する。

  会員テーブル `customers` と注文テーブル `orders` がある。`orders.customer_id` が NULL の行は、会員登録せずに購入したゲスト注文を表す。

  テーブル `customers`

  | id | name |
  | --- | --- |
  | 1 | 佐藤 |
  | 2 | 鈴木 |
  | 3 | 高橋 |
  | 4 | 田中 |

  テーブル `orders`

  | order_id | customer_id |
  | --- | --- |
  | 101 | 1 |
  | 102 | 3 |
  | 103 | NULL |
  | 104 | 3 |

  一度も注文していない会員を抽出しようとして、次の SQL 文を実行した（標準 SQL に従うものとする）。

  ```sql
  SELECT name
  FROM customers
  WHERE id NOT IN (SELECT customer_id FROM orders);
  ```

  実行結果として正しいものを次のうちから一つ選べ。

`id NOT IN (1, 3, NULL, 3)` は `id <> 1 AND id <> 3 AND id <> NULL AND id <> 3` と同じ意味です。NULL との比較 `id <> NULL` は真でも偽でもない UNKNOWN になるので、注文していない鈴木（`id = 2`）についても条件全体は「真 AND 真 AND UNKNOWN AND 真 = UNKNOWN」となります。`WHERE` 句は条件が真の行だけを残すため、1 行も出力されません。

### 各行の評価

| id | `id <> 1` | `id <> 3` | `id <> NULL` | `NOT IN` 全体 |
| --- | --- | --- | --- | --- |
| 1 | 偽 | 真 | UNKNOWN | 偽 |
| 2 | 真 | 真 | UNKNOWN | UNKNOWN |
| 3 | 真 | 偽 | UNKNOWN | 偽 |
| 4 | 真 | 真 | UNKNOWN | UNKNOWN |

どの行も真にならないので、結果は空です。

### 各選択肢の検討

- ①：意図した結果ですが、副問合せに NULL が含まれると `NOT IN` は真になりません。次のように `NOT EXISTS` を使うか、副問合せに `WHERE customer_id IS NOT NULL` を加えると、鈴木と田中が得られます。

  ```sql
  SELECT name
  FROM customers c
  WHERE NOT EXISTS (
    SELECT 1 FROM orders o WHERE o.customer_id = c.id
  );
  ```

- ②：`IN`（注文したことのある会員）の結果です。`IN` は NULL があっても一致する値があれば真になるので、こちらは期待どおりに動きます。
- ③：正しい。
- ④：NULL を「どの値とも異なる」と考えると、このように誤解しやすくなります。SQL の NULL は「不明な値」として扱われます。
- ⑤：副問合せの結果に NULL が含まれてもエラーにはならず、黙って空の結果が返ります。そのため誤りに気づきにくいのです。

### ポイント

- SQL は真・偽・UNKNOWN の 3 値論理で評価され、NULL との比較（`=`、`<>`、`<` など）は UNKNOWN になる。NULL かどうかの判定には `IS NULL` / `IS NOT NULL` を使う。
- `WHERE` は真の行だけを残す。UNKNOWN の行も除かれる。
- 「存在しない」ことの判定には、NULL の影響を受けない `NOT EXISTS` や、`LEFT JOIN … WHERE o.order_id IS NULL`（反結合）を使うのが安全である。

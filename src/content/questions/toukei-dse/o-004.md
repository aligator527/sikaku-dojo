passage: |
  ある EC サイトのデータベースに、次の 2 つのテーブルがある。

  テーブル `customers`

  | id | name | region |
  | --- | --- | --- |
  | 1 | 佐藤 | 東 |
  | 2 | 鈴木 | 西 |
  | 3 | 高橋 | 東 |
  | 4 | 田中 | 北 |

  テーブル `orders`

  | order_id | customer_id | amount |
  | --- | --- | --- |
  | 101 | 1 | 3000 |
  | 102 | 1 | 2000 |
  | 103 | 3 | 5000 |
  | 104 | 5 | 1000 |

  次の SQL 文を実行する（標準 SQL に従うものとする）。

  ```sql
  SELECT c.region,
         COUNT(o.order_id) AS n,
         SUM(o.amount)     AS total
  FROM customers c
  LEFT JOIN orders o ON c.id = o.customer_id
  GROUP BY c.region;
  ```
stem: |
  実行結果のうち、`region` が「西」の行について正しいものを次のうちから一つ選べ。
choices:
  - '`n` は 1、`total` は NULL となる。'
  - '`n` は 0、`total` は 0 となる。'
  - '`n` は 0、`total` は NULL となる。'
  - '「西」の行は結果に出力されない。'
  - '`n` は 1、`total` は 0 となる。'
answer: 3
---
`LEFT JOIN` では左側のテーブル（`customers`）のすべての行が残り、対応する注文がない顧客には `orders` 側の列が NULL で結合されます。「西」の鈴木さんには注文がないので、`order_id` と `amount` が NULL の 1 行になります。`COUNT(列)` は NULL を数えないので 0、`SUM` は NULL だけを集計すると NULL を返します。

### 結合後の中間結果

| region | name | order_id | amount |
| --- | --- | --- | --- |
| 東 | 佐藤 | 101 | 3000 |
| 東 | 佐藤 | 102 | 2000 |
| 西 | 鈴木 | NULL | NULL |
| 東 | 高橋 | 103 | 5000 |
| 北 | 田中 | NULL | NULL |

`customer_id = 5` の注文 104 は、`customers` に対応する顧客がないため結果に現れません。集計結果は、東：`n = 3`、`total = 10000`、西：`n = 0`、`total = NULL`、北：`n = 0`、`total = NULL` です。

### 各選択肢の検討

- ①・⑤：`COUNT(*)` なら行数を数えるので 1 になりますが、`COUNT(o.order_id)` は NULL でない値の個数なので 0 です。
- ②：`SUM` は対象がすべて NULL のとき 0 ではなく NULL を返します。0 にしたい場合は `COALESCE(SUM(o.amount), 0)` とします。
- ④：`INNER JOIN` の場合の結果です。`LEFT JOIN` では左側の行は必ず残ります。

### ポイント

- 集計関数は NULL を無視する（`COUNT(*)` だけは行を数える）。平均 `AVG` も NULL を除いた件数で割るので、欠測を 0 とみなす場合とは結果が異なる。
- 外部結合のあとで `WHERE o.amount > 0` のように右側の列で絞り込むと、NULL の行が落ちて実質的に内部結合になる。条件を `ON` 句に書くか `WHERE` 句に書くかで結果が変わる。

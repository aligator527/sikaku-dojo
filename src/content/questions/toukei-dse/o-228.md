Parquet は列ごとにデータをまとめて格納する列指向の形式で、スキーマ（列名とデータ型）をファイル内に持ちます。集計に必要な列だけを読めばよく（列の射影）、同じ列には似た値が並ぶので圧縮も効きやすくなります。行ごとに全列を書き並べる CSV では、数列だけが必要でも全体を読んで解析する必要があります。

### 各選択肢の検討

- ①：CSV はカンマ区切りのテキストで、型の情報を持ちません。読み込むソフトウェアが型を推測するため、郵便番号や商品コードの先頭の 0 が消える、日付の形式が変わるといった問題が起こります。
- ②：JSON はオブジェクト（キーと値の組）と配列を入れ子にでき、階層構造をもつデータ（API の応答など）の表現に広く使われます。行ごとに 1 つの JSON を書く JSON Lines 形式もあります。
- ③：Parquet は列指向で、大量データをまとめて書き込み、列単位で読む分析処理に向いています。1 行ずつの追加・更新には向かず、その用途には行指向のデータベースが使われます。
- ④：CSV の仕様（RFC 4180）は文字コードを UTF-8 に限っていません。日本語の環境では Shift_JIS の CSV も多く、BOM の有無も含めて読み込み時に文字コードを指定する必要があります。
- ⑤：正しい。列ごとの統計情報（最小値・最大値など）を使って、条件に合わない部分を読み飛ばすこともできます。

### ポイント

| 形式 | 構造 | 型情報 | 主な用途 |
| --- | --- | --- | --- |
| CSV | 行指向のテキスト（表形式） | なし | データ交換、表計算ソフト |
| JSON | 入れ子にできるテキスト | 文字列・数値・真偽値・null を区別 | Web API、設定ファイル |
| Parquet | 列指向のバイナリ | あり（スキーマ） | 大規模データの分析・DWH |

- テキスト形式は人が読めて扱いやすいが、大量データではサイズと解析時間が大きくなる。分析基盤では列指向形式（Parquet、ORC）がよく使われる。

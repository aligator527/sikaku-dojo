## 定義

非機能要件は、「どのような機能を提供するか」（機能要件）ではなく、「その機能をどの程度の品質で、どのような条件で提供するか」を定める要件です。例えば「受注を登録できる」は機能要件、「ピーク時に 3 秒以内に応答する」「年間稼働率 99.9% 以上」は非機能要件です。

## 非機能要求グレード

IPA は、非機能要件を発注者と受注者で漏れなく合意するためのツールとして**非機能要求グレード**を公開しています。六つの大項目で整理します。

| 大項目 | 内容の例 |
| --- | --- |
| 可用性 | 稼働時間、障害時の復旧目標、災害対策 |
| 性能・拡張性 | 応答時間、処理件数、将来の業務量の増加への対応 |
| 運用・保守性 | 運用時間、バックアップ、監視、保守の体制 |
| 移行性 | 移行の方式、データ移行の範囲、移行期間 |
| セキュリティ | 認証、アクセス制御、暗号化、ログ |
| システム環境・エコロジー | 設置環境、法令・規格への準拠、消費電力 |

項目ごとに複数のレベルを示し、システムの重要度に応じたモデルシステムを選んでから調整する、という使い方をします。

## 試験での問われ方

- **ITストラテジスト試験**：午前II で、利用者要件の中から非機能要件項目（可用性、性能、拡張性、運用性、保守性、移行性など）を選ぶ問題が出題されています。午後では、サービスレベルや投資額との兼ね合いで非機能要件の水準を決める場面が問われます。

## よくある誤り

- 業務手順や組織・権限など、業務要件に当たる項目を非機能要件と取り違える。
- 非機能要件を高く設定するほどよいと考える。水準を上げると費用も増えるため、業務への影響の大きさに見合った水準にします。

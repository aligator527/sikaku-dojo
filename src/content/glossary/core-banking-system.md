## 定義

勘定系システムは、銀行の業務のうち、お金の出入りを伴う取引を処理するシステムです。窓口、ATM、インターネットバンキングなどからの取引を受け付け、口座の残高を更新し、勘定（会計上の記録）を管理します。障害が起きると社会全体の決済に影響するため、非常に高い正確性・可用性・セキュリティが求められる、SoR（記録のためのシステム）の典型です。

## 銀行のシステムの主な区分

| 区分 | 役割 |
| --- | --- |
| 勘定系 | 預金・融資・為替の取引処理と残高の管理 |
| 情報系 | 顧客情報や取引データの分析、経営管理、営業支援 |
| 対外接続系 | 全銀システム（銀行間の振込）、カードネットワーク、日本銀行などとの接続 |
| チャネル系 | 窓口端末、ATM、インターネットバンキング、スマートフォンアプリ |

## 再構築の動向と論点

- メインフレーム上で長年改修を重ねたシステムは、保守の費用や技術者の確保が課題になっており、オープン系やクラウドへの移行、複数の銀行での共同利用（共同化）が進められています。
- フィンテック企業や非金融事業者との連携のために、勘定系の機能を API で外部に公開し、新しいサービスを素早く提供できる構成にする取組があります。
- 移行は社会的な影響が大きいため、十分なテストと段階的な移行、障害時の対応計画が不可欠です。

## 試験での問われ方

- **ITストラテジスト試験**：午後の事例で、新しい金融サービスを実現するための銀行勘定系システムの再構築が題材になり、再構築の進め方や、外部サービスとの連携のための要件が問われました。

## よくある誤り

- 顧客分析などを行う情報系システムと混同する。勘定系は取引の処理と残高の管理を担います。
- 勘定系の刷新を、機能の追加だけを目的とする計画として考え、移行リスクや他システムとの接続の影響を検討しない。

## 定義

オブジェクト指向は、現実の物や概念を、属性（データ）と操作（メソッド）を備えたオブジェクトとして表し、オブジェクトが互いにメッセージを送り合うことで処理を進める、という考え方でシステムを分析・設計・実装する方法です。同じ種類のオブジェクトのひな形を**クラス**、クラスから作られた個々のオブジェクトを**インスタンス**といいます。

## 基本の概念

| 概念 | 内容 |
| --- | --- |
| カプセル化 | 属性と操作をまとめ、内部の詳細を隠して、決められた操作を通してだけ扱えるようにする（情報隠蔽） |
| 継承 | スーパークラスの属性と操作を、サブクラスが引き継ぐ。サブクラスでは、引き継いだ操作を定義し直すこともできる（オーバーライド） |
| ポリモーフィズム（多態性） | 同じメッセージを送っても、受け取ったオブジェクトのクラスに応じて、それぞれ固有の動作をする |

## クラス間の関係

- **汎化・特化**（is-a の関係）：「乗用車は自動車の一種である」のように、一般的なクラスと特殊なクラスの関係。継承によって属性と操作が引き継がれる。
- **集約・コンポジション**（part-of の関係）：「自動車はエンジンを部品として持つ」のような全体と部分の関係。全体と部分の間で属性や操作が共有されるわけではない。
- **関連**：クラスのインスタンスどうしの一般的な結び付き。三つ以上のクラスの間や、同じクラスどうしにも定義できる。

UML のクラス図では、これらの関係を線の種類で描き分けます。

## 試験での問われ方

- **ITストラテジスト試験**：科目A-1 で、クラス間の関係として適切な記述（サブクラスでスーパークラスの操作を再定義できる）を選ぶ問題が出題されています。誤りの選択肢は、関連は二つのクラス間でしか定義できない、集約では全体と部分が属性と操作を共有する、などです。

## よくある誤り

- オーバーライド（サブクラスでの再定義）と、オーバーロード（同じ名前で引数の型や数が異なる操作を複数定義すること）を取り違える。
- 集約（全体と部分）でも、継承と同じように属性や操作が引き継がれると考える。
- サブクラスのインスタンスが、スーパークラスのインスタンスに処理を依頼して操作を実行すると考える。継承した操作は、自分自身の操作として実行します。

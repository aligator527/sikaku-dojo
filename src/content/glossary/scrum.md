## 定義

スクラムは、変化の多い環境で製品を開発するための枠組みです。最初にすべてを計画するのではなく、短い期間で作って見せ、その結果を見て計画を直す「経験主義」に立ち、**透明性・検査・適応**を柱とします。考え方と規則はスクラムガイドにまとめられています。

## 構成要素

| 区分 | 要素 | 内容 |
| --- | --- | --- |
| 責任 | プロダクトオーナー | プロダクトの価値を最大化する。プロダクトバックログの内容と並び順に責任を持つ |
| | スクラムマスター | スクラムが正しく実践されるよう、チームと組織を支援する。指示・命令する管理者ではない |
| | 開発者 | 各スプリントで、使える状態の成果物（インクリメント）を作る |
| イベント | スプリント | 1 か月以内の固定の期間。ほかのイベントはすべてこの中で行う |
| | スプリントプランニング | スプリントの開始時に、スプリントゴールと実施する作業（スプリントバックログ）を決める |
| | デイリースクラム | 開発者が毎日 15 分で、スプリントゴールへの進捗を確かめ、その日の計画を調整する |
| | スプリントレビュー | ステークホルダに成果を示し、プロダクトゴールへの進捗を話し合って、プロダクトバックログを調整する |
| | スプリントレトロスペクティブ | スプリントの最後に、人・プロセス・ツールなどを振り返り、改善策を決める |
| 作成物 | プロダクトバックログ | プロダクトに必要なものを並べた一覧。目標はプロダクトゴール |
| | スプリントバックログ | そのスプリントで行う作業の計画。目標はスプリントゴール |
| | インクリメント | 完成の定義を満たした成果物 |

## 試験での問われ方

- **ITストラテジスト試験**：科目A-1 で、ステークホルダに作業の結果を示し、プロダクトゴールに対する進捗を話し合ってスコープを調整するイベント（スプリントレビュー）を、スプリントプランニング・デイリースクラム・レトロスペクティブの中から選ぶ問題が出題されています。

## よくある誤り

- スプリントレビューとレトロスペクティブを取り違える。レビューは「何を作ったか（プロダクト）」、レトロスペクティブは「どう作ったか（プロセス）」を検査します。
- デイリースクラムを、ステークホルダへの進捗報告の場だと考える。開発者自身が計画を調整するための場です。
- スクラムマスターを、チームに作業を割り当てるプロジェクトマネージャだと考える。

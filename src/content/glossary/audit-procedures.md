## 定義

監査手続は、監査人が監査の結論（意見）を形成するために、監査項目ごとに**十分かつ適切な監査証拠**を集める具体的な手続です。監査証拠には、量が足りていること（十分性）と、結論を裏付ける力があること（適切性）の両方が求められます。実施した手続と入手した証拠は、監査調書に記録します。

監査計画の立案、監査チームの編成、報告書の作成は、監査の別の段階の作業であり、監査手続には当たりません。

## 主な監査技法

| 技法 | 内容 |
| --- | --- |
| チェックリスト法 | あらかじめ作った質問項目に回答を求めて確かめる |
| ドキュメントレビュー法 | 規程・設計書・記録などの資料や文書を入手し、内容を点検する |
| インタビュー法 | 関係者に口頭で質問し、回答を得る |
| ウォークスルー法 | データの生成から入力・処理・出力・利活用までの一連の流れをたどり、そこに組み込まれたコントロールを確かめる |
| 突合・照合法 | 関連する記録どうしを照らし合わせ、一致しているかを確かめる |
| 現地調査法 | 現場に出向いて、業務の実施状況などを直接観察する |

コンピュータを使う監査技法（CAAT）には、監査人が用意したテストデータを監査対象のプログラムで処理させ、期待した結果と比べる**テストデータ法**、監査用のモジュールを組み込んで条件に合うデータを抽出・記録する監査モジュール法、本番のシステムに監査用の架空の口座などを設けて処理を確かめる ITF 法などがあります。

インタビュー法で得た回答は、それだけでは証拠としての力が弱いため、文書や記録で裏付けを取ることが重要です。

## 試験での問われ方

- **ITストラテジスト試験**：科目A-1 で、システム監査における監査手続の説明として適切なもの（十分かつ適切な証拠を入手するための手続）を選ぶ問題や、ウォークスルー法の説明を、ドキュメントレビュー法・インタビュー法・テストデータ法の説明と見分ける問題が出題されています。

## よくある誤り

- 監査計画の策定や監査報告書の作成を、監査手続だと考える。
- ウォークスルー法を、関係者に口頭で問い合わせる方法だと考える。それはインタビュー法です。
- ソフトウェア開発のレビュー手法の「ウォークスルー」（作成者が説明して問題点を指摘してもらう）と混同する。

## 手順

```python
def binary_search(a, x):
    lo, hi = 0, len(a) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if a[mid] == x:
            return mid
        elif a[mid] < x:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1
```

1 回の比較で探索範囲がほぼ半分になるので、$n$ 個の要素に対する比較の回数は最悪でも $\lfloor\log_2 n\rfloor + 1$ 回です。$n = 1000$ なら最大 10 回、$n = 10^6$ でも最大 20 回で済みます。先頭から順に調べる線形探索は最悪 $n$ 回なので、何度も検索するなら、一度 $O(n \log n)$ で並べ替えてから二分探索する方が有利です。

## 前提と注意

- **整列済みであること**：昇順（または降順）に並んでいない配列には使えません。
- **ランダムアクセス**：中央の要素に定数時間でアクセスできる配列が前提で、連結リストでは効率が出ません。
- **境界条件**：`lo <= hi` か `lo < hi` か、`mid + 1` か `mid` かを取り違えると、無限ループや取りこぼしが起きます。
- **重複した値**：同じ値が複数あると、どの位置が返るかは実装によります。「x 以上の最初の位置」を返す形（Python の `bisect_left`）にしておくと、挿入位置や、ある値以下の要素の個数を求めるのにも使えます。

## 応用

- 単調な関数 $f$ について $f(x) = 0$ となる $x$ を区間を半分にしながら探す二分法（数値計算）。
- 「条件を満たす最小の値」を答えの候補の範囲で二分探索する方法（例：締切に間に合う最小の作業人数）。
- データベースの索引に使う B 木などの探索木も、同じ考え方で探索の範囲を絞ります。

## 試験での問われ方

統計検定データサイエンスエキスパートでは、二分探索のコードで特定の値を探すときの比較回数や、変数 `lo`・`hi` の変化をたどる問題、線形探索との計算量の比較が出ます。

## よくある誤り

- 並んでいない配列に二分探索を使う。
- 比較の回数を、線形探索と同じく $n$ に比例すると見積もる（$n$ が 1000 倍になっても、最悪の比較回数は約 10 回増えるだけ）。

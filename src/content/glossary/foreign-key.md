## 定義

注文表の `customer_id` が会員表の主キー `id` を参照するとき、`customer_id` を外部キーといいます。外部キーを宣言すると（参照制約）、データベースは次のことを保証します。

- 外部キーの値は、参照先の表に存在する値か NULL である（NOT NULL 制約がなければ NULL も許される）。
- 参照されている行を削除・更新するときは、宣言した動作に従う。

## 参照先を削除・更新するときの動作

| 指定 | 参照先の行を削除したときの動作 |
| --- | --- |
| RESTRICT / NO ACTION（既定） | 参照している行があれば、削除そのものを拒否する |
| CASCADE | 参照している行も連鎖して削除する |
| SET NULL | 参照している行の外部キーを NULL にする |
| SET DEFAULT | 参照している行の外部キーを既定値にする |

更新（ON UPDATE）についても同様に指定できます。

## 分析での意味

外部キーは表どうしの結合のキーになります。正規化によって分けた表は、外部キーで結合すれば元の情報に戻せます。NULL を許す外部キー（担当者が未定の案件で担当者番号を NULL にしている場合など）があると、内部結合ではその行が結果から消え、外部結合では会員側の列が NULL になります。また、参照先の主キーは一意なので、「多」の側の表に外部キーをもつ 1 対多の関係として結合の行数を見積もれます。

## 試験での問われ方

統計検定データサイエンスエキスパートでは、主キー・外部キーで関連づけた表の結合結果、外部キーが NULL の行の扱いが問われます。ITストラテジストの午前 I では、参照制約のある表で参照先の行を削除したときに何が起こるか（削除の拒否、連鎖削除など）を問う問題が出ます。

## よくある誤り

- 外部キーの列には重複した値が入らないと考える（1 人の会員が何度も注文するように、同じ値が何行にも現れてよい）。
- 外部キーには NULL が入らないと考える（NOT NULL 制約を付けない限り入りうる）。

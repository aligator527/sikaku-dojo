## 種類

```sql
SELECT c.name, o.amount
FROM customers c
LEFT JOIN orders o ON c.id = o.customer_id;
```

- **内部結合（INNER JOIN）**：結合条件を満たす行の組だけを出力します。相手のいない行は消えます。
- **左外部結合（LEFT JOIN）**：左の表の行はすべて残し、相手がいなければ右の表の列を NULL で埋めます。右外部結合（RIGHT JOIN）はその逆、完全外部結合（FULL OUTER JOIN）は両方を残します。
- **交差結合（CROSS JOIN）**：すべての行の組合せ（直積）。$m$ 行と $n$ 行なら $mn$ 行。

## 行数の変化に注意

結合キーが一方の表で一意でない（1 対多の関係）と、もう一方の行が複製されます。たとえば 1 件の注文に 2 行の配送記録があれば、注文表と配送表を結合した結果では、その注文が 2 行になります。そのまま `SUM(amount)` をとると注文金額を二重に数えてしまうので、先に集計してから結合するか、`COUNT(DISTINCT order_id)` などを使います。

## 外部結合と集計

注文のない会員も 0 件として数えたいときは、会員表を左にした LEFT JOIN のあとで `COUNT(o.order_id)` を使います。`COUNT(*)` は NULL で埋めた行も 1 と数えるので、注文のない会員が 1 件と数えられてしまいます。また、右の表の列に対する条件を WHERE に書くと、NULL で埋めた行が消えて内部結合と同じ結果になります。右の表を絞りたいときは、条件を ON 句に書きます。

## 試験での問われ方

統計検定データサイエンスエキスパートでは、2 つの表と結合を含む SQL 文から結果の行数や値を求める問題が典型です。1 対多の結合による行の重複、LEFT JOIN と COUNT の組合せ、NULL で埋められた行の扱いがよく問われます。

## よくある誤り

- 結合後の行数は左の表の行数と同じだと思い込む（1 対多なら増える）。
- 外部結合のあとの WHERE 句で右の表の列を条件にし、外部結合の意味をなくしてしまう。

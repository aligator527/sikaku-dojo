## 定義

仮想化は、物理的なハードウェア資源をソフトウェアで抽象化し、実際の構成とは独立した「仮想的な」資源として利用者に見せる技術です。代表的なサーバ仮想化では、1 台の物理サーバの上で複数の仮想マシン（それぞれが独自の OS をもつ）を動かせます。

## 方式

| 方式 | 構成 | 特徴 |
| --- | --- | --- |
| ホスト型 | ハードウェア → ホスト OS → 仮想化ソフトウェア → ゲスト OS | 既存の OS 上に導入でき手軽。ホスト OS を経由する分、処理が重い |
| ハイパーバイザ型 | ハードウェア → ハイパーバイザ → ゲスト OS | ホスト OS を介さないので効率がよい。サーバ統合の主流 |
| コンテナ型 | ハードウェア → ホスト OS → コンテナエンジン → コンテナ | ゲスト OS を起動せず、ホスト OS のカーネルを共有する。軽量で起動が速い |

コンテナはカーネルを共有するため、ホスト OS と異なるカーネルを必要とする OS は動かせず、仮想マシンに比べて分離の強さも劣ります。

## 利点と注意点

- 複数の物理サーバを少数のサーバに集約（サーバ統合）でき、設置スペース・電力・保守の費用を減らせます。
- 必要なときに仮想マシンを作って資源を割り当てられるので、環境の準備が速くなります。クラウドサービス（IaaS など）の基盤でもあります。
- **ライブマイグレーション**を使うと、仮想マシンを動かしたまま別の物理サーバへ移せるので、保守や負荷分散の際にサービスを止めずに済みます。
- 一方、1 台の物理サーバの故障が多くの仮想マシンに影響するので、物理サーバ側の冗長化が重要になります。

## 試験での問われ方

- **中小企業診断士試験**：経営情報システムで、ホスト型・ハイパーバイザ型・コンテナ型の違いや、ライブマイグレーションの説明が問われています。
- **E資格**：開発・実行環境の一つとして、仮想マシンとコンテナの違い（カーネルの共有）が出題されます。
- **ITストラテジスト試験**：サイバーフィジカルシステムなどの選択肢の一つとして、サーバの仮想化の説明が出てきます。

## よくある誤り

- ハイパーバイザ型とホスト型の構成を取り違える。ハードウェアの上で直接ハイパーバイザが動くのがハイパーバイザ型です。
- コンテナごとにゲスト OS が起動すると考える。コンテナはホスト OS のカーネルを共有します。
- ライブマイグレーションを「停止してから移す」技術だと考える。稼働させたまま移すのが特徴です。

## 定義

サービスマネジメントは、情報システムを「顧客に価値を届けるサービス」としてとらえ、その計画・設計・移行・提供・改善を管理する活動です。要求事項は国際規格 ISO/IEC 20000-1（JIS Q 20000-1）に、実践のための手引きは ITIL（英国政府が始めたベストプラクティス集）にまとめられています。

## 主なプロセス

| プロセス | 主な活動 |
| --- | --- |
| サービスレベル管理 | 提供するサービスとサービスレベル目標を顧客と合意して SLA に記し、達成状況を監視・報告・見直す |
| キャパシティ管理（容量・能力管理） | 資源の現状を調整・最適化し、将来の需要を予測して資源の計画を立てる |
| サービス可用性管理・サービス継続管理 | 合意した可用性を満たすようにし、災害などで中断しても合意した時間内に復旧できるよう、事業影響度や復旧の優先順位を明確にする |
| 予算業務及び会計業務 | サービスの提供に必要な予算を立て、費用を管理する |
| インシデント管理 | 障害などで中断・低下したサービスを、回避策も使って、できるだけ早く元の状態に戻す |
| 問題管理 | インシデントの根本原因を突き止めて取り除き、再発を防ぐ |
| 変更管理 | システムやサービスへの変更のリスクと影響を評価し、承認したうえで実施させる |
| 構成管理 | サービスを構成する機器・ソフトウェア・文書とその関係を記録し、最新に保つ |

利用者からの問合せや障害の連絡を一元的に受け付ける窓口を、サービスデスクといいます。

## インシデント管理と問題管理の違い

インシデント管理の目的は**サービスの早期回復**で、原因が分からなくても、再起動や代替手段などの回避策でまず業務を再開させます。問題管理の目的は**根本原因の除去と再発防止**で、同じインシデントが繰り返し起きる場合などに、時間をかけて原因を分析します。

## 試験での問われ方

- **ITストラテジスト試験**：科目A-1 で、サービスレベル管理の活動を、キャパシティ管理・予算業務・サービス継続管理の活動と見分ける問題や、SLA で定めたサービス可用性の目標から許される停止時間を求める問題が出題されています。

## よくある誤り

- インシデント管理で、根本原因が分かるまでサービスの回復を待つ。まず回復を優先し、原因の究明は問題管理で行います。
- 将来の資源要件を予測する活動を、サービスレベル管理だと考える。それはキャパシティ管理です。
- サービス継続管理と、事業全体を対象とする BCP を同じものと考える。サービス継続管理は、BCP を支える IT サービスの側の活動です。

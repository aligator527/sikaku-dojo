## 定義

SQL インジェクションは、Web アプリケーションが利用者の入力値を文字列として連結して SQL 文を作っているときに、入力の中に SQL の記号や命令を混ぜて、開発者の意図と異なる SQL 文を実行させる攻撃です。

## 例

会員番号を受け取って、次のように SQL 文を組み立てるとします。

```sql
SELECT * FROM 会員 WHERE 会員番号 = '（入力値）'
```

入力値として `' OR '1'='1` を与えると、条件は「会員番号 = '' OR '1'='1'」となって常に真になり、全会員の情報が表示されてしまいます。同じ方法で、データの改ざんや削除、認証の回避なども行われます。

## 対策

- **根本的な対策**：SQL 文の組立てをすべて**プレースホルダ**で行う。SQL 文の骨組みを先に確定させ、入力値は後から「値」として当てはめるので、入力が SQL の命令として解釈されることがありません。
- **保険的な対策**：データベースのエラーメッセージを画面にそのまま表示しない。アプリケーションが使うデータベースのアカウントの権限を必要最小限にする。WAF（Web Application Firewall）で攻撃の疑いがある通信を遮断する。

## 試験での問われ方

- **ITストラテジスト試験**：科目A-1 の OS コマンドインジェクション対策を問う問題で、「SQL 文の組立ては全てプレースホルダで実装する」が SQL インジェクション対策の選択肢として出てきます。攻撃と根本的な対策を組で覚えておくと、ほかの攻撃を問う問題でも選択肢を絞り込めます。

## よくある誤り

- 入力値の検査や特殊文字のエスケープだけで十分だと考える。漏れが生じやすいため、プレースホルダが根本的な対策とされます。
- プレースホルダを、OS コマンドインジェクションやクロスサイトスクリプティングの対策と取り違える。
- WAF を導入すればアプリケーションの修正は不要だと考える。WAF は保険的な対策です。

## 定義

Web アプリケーションの中には、メールの送信やファイルの変換などのために、プログラムの中からシェル（コマンドを解釈して実行する OS の機能）を経由して外部のコマンドを呼び出すものがあります。このとき、利用者の入力値をそのままコマンドの一部に組み込んでいると、攻撃者は「;」や「|」などの記号でコマンドを区切り、本来とは別のコマンドを続けて実行させることができます。これが OS コマンドインジェクションです。

サーバ上で任意のコマンドが動くため、情報の漏えい、ファイルの改ざんや削除、マルウェアの設置、他のシステムへの攻撃の踏み台化など、被害は深刻になります。

## 対策

- **根本的な対策**：シェルを起動できる言語機能を使わずに実装する。外部のプログラムを呼び出す必要があるときは、シェルを介さずに引数を直接渡す仕組みやライブラリ関数を使う。
- **保険的な対策**：入力値を許可した文字の並びだけに制限する。アプリケーションを必要最小限の権限で動かす。

## 主な脆弱性と根本的な対策

| 脆弱性 | 根本的な対策 |
| --- | --- |
| OS コマンドインジェクション | シェルを起動できる言語機能を使わない |
| SQL インジェクション | SQL 文の組立てをすべてプレースホルダで行う |
| ディレクトリトラバーサル | 外部からファイル名を直接指定させない、ファイル名からディレクトリ名を取り除く |
| バッファオーバーフロー | 直接メモリにアクセスできる言語機能を避ける、書き込む長さを検査する |
| クロスサイトスクリプティング | 出力する値をエスケープする |

## 試験での問われ方

- **ITストラテジスト試験**：科目A-1 で、OS コマンドインジェクションの対策を、プレースホルダ（SQL インジェクション対策）やファイル名のディレクトリ検査（ディレクトリトラバーサル対策）などと見分ける問題が出題されています。上の表のように、攻撃と根本的な対策を組で覚えるのが近道です。

## よくある誤り

- プレースホルダを使えば OS コマンドインジェクションも防げると考える。プレースホルダは SQL 文のための対策です。
- 入力値の検査だけで十分だと考える。検査は漏れが生じやすい保険的な対策で、シェルを使わない実装が根本的な対策です。

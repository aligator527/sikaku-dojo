## 定義

TLS は、Web ブラウザと Web サーバの間などの通信を保護するプロトコルです。TCP の上、アプリケーションの下で動き、HTTP を TLS で保護したものが HTTPS です。前身の SSL と合わせて「SSL/TLS」と呼ばれることもあります。

TLS が提供する機能は次の三つです。

- **機密性**：通信内容を共通鍵暗号で暗号化し、盗聴を防ぐ。
- **完全性**：改ざんされていないことを、メッセージ認証の仕組みで確かめる。
- **認証**：サーバのデジタル証明書を検証し、接続先が本物であることを確かめる（必要に応じてクライアントも認証する）。

## 通信の流れ

1. 接続の最初（ハンドシェイク）で、使用する暗号方式を決め、サーバの証明書を検証する。
2. 公開鍵暗号の技術を使った鍵交換で、その通信だけに使う共通鍵を安全に共有する。
3. 以降のデータは、処理の速い共通鍵暗号で暗号化してやり取りする。

公開鍵暗号と共通鍵暗号を組み合わせる、ハイブリッド方式の代表例です。SSL 2.0・3.0 と TLS 1.0・1.1 には弱点が見つかっており、現在は TLS 1.2 以降（特に TLS 1.3）を使います。

## 試験での問われ方

- **ITストラテジスト試験**：科目A-1 で、OSI 基本参照モデルにおける IPsec・L2TP・TLS の位置関係や、ネットワーク層で暗号化する技術（IPsec）との違いが問われています。TLS を使った VPN は SSL-VPN と呼ばれます。
- **中小企業診断士試験**：経営情報システムで、暗号技術やデジタル証明書の利用場面として出てきます。

## よくある誤り

- TLS はネットワーク層で IP パケットを暗号化すると考える。それは IPsec です。
- TLS を使えば、サーバに保存されたデータや端末内のデータまで守られると考える。保護されるのは通信の途中だけです。
- 証明書を使った HTTPS のサイトなら安全だと考える。フィッシングサイトでも証明書は取得できるので、接続先のドメイン名の確認が必要です。

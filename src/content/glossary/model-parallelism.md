## 分け方

- **パイプライン並列**：モデルを層の境界で $p$ 個のステージに分け、各 GPU が連続した層を担当する。前のステージの出力（活性）を次のステージに送り、逆伝播では勾配を逆向きに送ります。
- **テンソル並列**：1 つの層の重み行列を列や行で分割し、複数の GPU で行列積の一部ずつを計算して結果を集める。Transformer の注意機構や MLP の大きな行列に使われます。

データ並列化では各 GPU がモデル全体を持つのに対し、モデル並列化では各 GPU がモデルの一部しか持たないので、1 台のメモリに収まらないモデルを扱えます。

## パイプラインのバブル

単純にステージを分けただけだと、あるステージが計算している間、他のステージは待つだけになります。そこでミニバッチを $m$ 個のマイクロバッチに分け、流れ作業のように順に流します（GPipe）。それでも最初と最後に GPU が遊ぶ時間（バブル）が残り、その割合は上の式で表されます。$p = 4$、$m = 12$ なら $3/15 = 0.2$ で、マイクロバッチを増やすほどバブルは小さくなります。順伝播と逆伝播を交互に進める 1F1B のスケジュールでは、同時に保持する活性を減らせます。

## 通信の違い

| | データ並列化 | モデル並列化 |
| --- | --- | --- |
| 各 GPU が持つもの | モデル全体の複製 | モデルの一部 |
| 主な通信 | 勾配の集約（All-Reduce） | 層の境界での活性と勾配（パイプライン）、層の中の部分結果（テンソル） |
| 前提 | モデルが 1 台に収まる | モデルが大きい |

テンソル並列は層の中で頻繁に通信するので、同じノード内の高速な接続（NVLink など）の GPU どうしで使うのが一般的です。大規模言語モデルの学習では、データ並列・テンソル並列・パイプライン並列を組み合わせます（3D 並列）。

## 試験での問われ方

E資格（シラバス 2026 の並列分散処理：モデル並列化、データ並列化）では、2 つの方式の違いと使い分け、パイプライン並列のバブルの計算、通信される内容の違いが出題されます。

## よくある誤り

- モデル並列化でも各 GPU がモデル全体を持つと考える。
- パイプライン並列では全ステージが常に同時に計算できると考える（バブルがある）。
- モデル並列化の通信は勾配の集約だけだと考える（活性も送る）。

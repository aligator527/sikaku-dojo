## 定義

ハッシュ関数は、入力データの長さにかかわらず、決まった長さの値（ハッシュ値、メッセージダイジェスト）を出力する関数です。入力が 1 ビットでも変わると、ハッシュ値は大きく変わります。セキュリティに使う**暗号学的ハッシュ関数**には、次の性質が求められます。

| 性質 | 内容 |
| --- | --- |
| 原像計算困難性（一方向性） | ハッシュ値から元のデータを求めることが難しい |
| 第 2 原像計算困難性 | あるデータと同じハッシュ値になる別のデータを見つけることが難しい |
| 衝突困難性 | 同じハッシュ値になる二つのデータの組を見つけることが難しい |

代表例は SHA-2（SHA-256 など）と SHA-3 です。MD5 や SHA-1 は衝突を作る方法が見つかっており、新しいシステムでは使いません。

## 主な用途

- **改ざん・破損の検知**：配布元が公開するハッシュ値と、手元で計算したハッシュ値を比べる。
- **デジタル署名**：文書全体ではなく、そのハッシュ値に署名する。
- **パスワードの保存**：パスワードそのものではなく、ソルトを加えてハッシュ化した値を保存する。
- **証拠の同一性の確認**：デジタルフォレンジックスで、保全したデータが元のデータと同じであることを示す。
- **攻撃の痕跡の共有**：マルウェアのファイルのハッシュ値を、侵害の指標（IoC）として共有する。

データ構造のハッシュ表（ハッシュテーブル）で使うハッシュ関数は、高速に分散させることが目的で、暗号学的な強さは求められません。

## 試験での問われ方

- **ITストラテジスト試験**：科目A-2 のセキュリティ分野で、デジタル署名の仕組み、OCSP のリクエストの内容、IoC やデジタルフォレンジックスの説明の中に、ハッシュ値の利用が繰り返し出てきます。
- **中小企業診断士試験**：経営情報システムで、デジタル署名の作成手順として出てきます。
- **統計検定 データサイエンスエキスパート**：データファイルの完全性の確認や ID の仮名化など、分析の現場でのハッシュ関数の使い方と性質（出力が固定長であること、入力が少し変わるとハッシュ値が大きく変わること）が問われています。

## よくある誤り

- ハッシュ値から元のデータを復元（復号）できると考える。ハッシュ関数は暗号化とは異なり、元に戻すことを想定していません。
- メールアドレスや電話番号をハッシュ値に置き換えれば、元の値は推測されないと考える。取りうる値が限られるデータは、候補を片端からハッシュ化して照合すれば分かってしまうので、ソルトを加えるなどの工夫が必要です。
- ハッシュ値が一致すれば、送信者も確かめられると考える。ハッシュ値は誰でも計算し直せるので、送信者の確認にはデジタル署名やメッセージ認証コードが必要です。
